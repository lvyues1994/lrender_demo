# Presentation boundary verification
Unit: `QT_QPA_PLATFORM=offscreen ctest --test-dir build/plan-debug -L unit --output-on-failure`.
Production readback accepts only prepared/probed matching generation+actual physical extent. OwnedFrame retains source storage; copyImage explicitly unpacks low-byte RGBA into Qt-owned top-row-first RGBA8888 (portable, no host-endian reinterpret_cast). Stale display rejection does NOT cancel/account a submitted renderer frame.
Session owns World/targets; adapter never calls targets(). All control calls and callbacks GUI, completions always queued. Keep the adapter/session cleanup owner independent of view ObjectScope; no GUI sync_wait/flush/join. Readback core keeps outstanding cleanup callbacks alive even if wrapper is dropped. Injected boundary must eventually report completion and must not throw from public callbacks.
A switch stops admission, awaits all submitted senders, begins adapter drain, destroys old target, releases old path, prepares/probes new path, then publishes new target+generation together. PresentationTransition encodes this operation order, not actual renderer integration. Close during prepare cooperatively waits candidate completion/cleanup and never publishes it. Unsupported is an explicit error; Readback is not backend=cpu. Default snapshot path before readiness is not evidence of fallback.
Native policy invalidation callback runs on GUI outside mutex, increments serial once, replays already-invalid state to late subscriber. Session must synchronously stop new admissions and schedule drain/rebuild; P6/P9 wire this to actual sessions. Invalid lease refuses new surface creation; existing submitted GPU work must still settle. Worker NativePresenterCleanup privately acknowledges only after settle -> actual presenter.flush -> release target/other owners -> unique presenter destruction. GUI host release remains last. P9 worker adapter integration is still pending; policy tests are NOT GPU sharing proof.
Real probe: `build/plan-debug/demo_qt_vulkan_probe --require-shared --frames 24` on a valid DISPLAY/xcb session. It must report matching UUIDs, importsMemory/syncFiles, sharesBuffersWith=1, sharedShown>0 and presented capture pixels. Offscreen negative `QT_QPA_PLATFORM=offscreen ... --require-shared` must exit 1, not 77.
Opt in strict CTest with `cmake -S . -B build/plan-debug -DDEMO_ENABLE_STRICT_SHARED_TEST=ON`, then `ctest --test-dir build/plan-debug -R '^strict_shared$' --output-on-failure -V`. No SKIP_RETURN_CODE set on strict_shared. Default OFF avoids requiring GPUs on ordinary unit workers; normal platform probe may return 77, which is a skip, never acceptance. Do not run strict shared with offscreen unless verifying the expected failure.
Fractional DPR: Qt qRound physicalExtent is only requested host geometry. Actual WSI image extent is authoritative; P9 must feed that result into target/frame acceptance/history boundaries, allowing documented one-pixel rounding reconciliation rather than claiming exact Qt==WSI. This is NOT implemented or validated by P4 fake. No per-frame std::async in production adapter; existing bounded probe waiter is probe-only.

Constructor failure acknowledgement is private too: NativePresenterCleanup::construct records failure only after factory stack unwinding; retired lease cannot create a new surface. Callbacks must not throw; their captured event targets must remain valid until independent cleanup completion.

All original six adapter signatures remain unchanged. The single additional virtual setFrameContext(generation,extent) binds filtering through the base interface that future RenderSession owns; no dynamic_cast or concrete adapter dependency is required. Session still performs its own current-state display gate while awaiting old completions, before adapter drain.
